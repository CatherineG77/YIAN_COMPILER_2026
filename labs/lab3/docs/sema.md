# 语义分析实验说明（Sema）

## 1. 实验目标

本实验要求你基于给定模板实现语义分析器（Semantic Analyzer），对语法分析器（Parser）输出的 AST 转换为带有语义信息的 AST。通过本实验，你将掌握：

- 如何设计和实现一个语义分析器来处理复杂的语言结构。
- 如何追踪符号的定义和使用。
- 如何进行类型检查。

### 3.3 数据结构

#### 符号相关

在 `symbol.an` 中

- **符号**(`Symbol`): 代表程序中的一个有名字的实体, 符号包括: 函数、结构体、枚举、变量四种. 结构体的字段和枚举的成员理论上也被视为符号, 但是因为他们只能在特定的上下文中被访问, 因此我们不将他们作为符号管理. 符号包含以下信息:
  - 名字
  - 符号类型(函数/结构体/枚举/变量)
  - 类型信息(通过 `type_id` 引用类型上下文中的类型信息)
- **符号上下文**(`SymbolCtx`): 管理当前作用域中可见的符号, 包括全局符号和局部符号, 符号上下文需要支持嵌套, 即在一个作用域中定义的符号在其内部的子作用域中也是可见的, 但是在父作用域中不可见。
  - 要求支持变量遮蔽: 在一个作用域中定义的符号如果与父作用域中的符号同名, 则在当前作用域中访问该名字时, 应该访问到当前作用域中的符号, 而不是父作用域中的符号。
  - 每个符号通过一个唯一的 `symbol_id` 进行标识

#### 类型相关

在 `type.an` 中

- **类型**(`Type`): 代表程序中的一种类型, 包括基本类型(如 `i32`, `bool`), 结构体类型, 枚举类型, 函数类型等. 类型包含以下信息:
  - 类型种类(整数类型/布尔类型/结构体类型/枚举类型/函数类型等)
  - 类型引用信息, 某些类型可能会引用其他类型(比如结构体类型会引用它的字段类型, 数组类型会引用它的元素类型等), 通过 `type_id` 引用类型上下文中的其他类型信息
- **类型上下文**(`TypeCtx`): 管理程序中定义的所有类型, 包括基本类型和用户定义的类型(结构体类型、枚举类型、函数类型等).
  - 要求支持类型递归定义, 即在一个类型的定义中引用它自己(直接或间接), 例如链表节点的定义
  - 要求支持类型合法性检查, 能够计算出大小的类型是合法的, 不能计算出大小的类型(比如自己直接或间接包含自己)是非法的
  - 每个类型通过一个唯一的 `type_id` 进行标识

#### AST 相关

在 `hir.an` 中

- **HIR**(`HIR`): 代表程序的中间表示, 是一个带有语义信息的 AST. HIR 中的每个节点都带有类型信息和符号链接, 例如一个变量引用节点会链接到符号表中实际的变量定义, 一个表达式节点会带有该表达式的类型信息等.

**HIR** 与语法分析阶段生成的 AST 的区别:

- 删除元数据节点: 删除语法分析阶段生成的 AST 中, 不生成实际执行代码的节点, 例如结构体定义、枚举定义、函数签名和变量声明等, 这些节点的信息会被记录在符号表和类型上下文中
- 循环语句合并: **HIR** 中只存在一种循环: `loop`, 其他循环语句(`while`, `for`)会被转换成 `loop` 和条件判断的组合
- 表达式的类型与左值性: **HIR** 中的每个表达式节点都带有类型信息, 同时还会标记该表达式是否是一个左值(即是否可以出现在赋值语句的左边)
  - 所有变量都是左值
  - 解引用运算的结果是一个左值
  - 字段访问表达式: 如果访问的对象是一个左值, 则该字段访问表达式也是一个左值
  - 索引表达式: 如果访问的对象是一个左值, 则该索引表达式也是一个左值
  - 其余表达式都是右值
- 自动解引用: 本次实验所实现的语言要求在使用字段访问运算符 `.` 时, 如果访问的对象是一个指针类型, 则会进行自动解引用, 也就是说, `a.b` 会被解析为 `(*a).b` 如果 `a` 是一个指针类型. 这个机制会执行无限次, 直到访问到一个非指针类型为止. 解引用运算对应的 AST 节点需要的 **HIR** 中显式的表示出来

### 3.4 算法思路

语义分析的核心是 `Sema::analyze()` 方法, 其主要流程如下:

1. 扫描全局作用域中定义的函数、结构体、枚举, 将他们记录为符号表中的全局符号
2. 解析全局作用域中所有的函数签名, 结构体和枚举定义
3. 解析所有的函数体, 解析过程中:
   1. 维护一个符号表用于新增局部变量, 以及追踪当前作用域中可见的符号
   2. 将每个语句中的符号引用链接到符号表中实际的定义
   3. 进行类型检查
   4. 生成带有语义信息的 AST

我们将`扫描一次整个程序, 并进行某些处理`的行为称为一个 `PASS`, 上述流程包含 3 个 PASS

### 3.5 全局符号处理

在全局作用域中, 允许定义函数、结构体和枚举, 我们要求全局作用域中的符号只要在任意位置定义过一次, 就可以在全局作用域中的任意位置被引用。因此在扫描具体的函数之前, 需要两个 PASS 来处理全局符号:

#### PASS 1: 收集全局符号

在第一个 PASS 中, 我们扫描整个程序, 收集全局作用域中定义的函数、结构体和枚举的名字, 将他们记录到符号表中, 注意此时我们并不需要解析他们的具体定义, 只需要知道他们的名字和类型(函数/结构体/枚举)即可。

这个 PASS 需要创建一个**符号上下文**以及一个**类型上下文**, 将全局符号记录到两个上下文中, 以便后续的 PASS 使用。

之所以不能解析全局符号的具体定义, 是因为全局符号之间可能存在互相引用的情况(比如, 结构体 A 引用结构体 B, 或者函数 C 的返回类型是结构体 D), 我们必须先知道所有全局符号的名字, 才能正确解析他们的定义。

#### PASS 2: 解析全局符号定义

在第二个 PASS 中, 我们再次扫描整个程序, 这一次我们解析全局符号的具体定义, 包括:

- 函数的签名, 包括参数列表和返回类型
- 结构体的字段
- 枚举的成员

此时全局作用域中的所有符号都已经被记录在符号表中, 因此我们可以正确解析他们的定义。这个 PASS 不改变符号上下文, 但是会更新类型上下文中的类型信息, 因为函数的签名、结构体的字段和枚举的成员都会影响类型系统。

注意此阶段只解析函数的签名, 不能解析函数体. 解析函数体的过程中, 我们需要对函数调用进行类型检查, 因此必须确保在解析函数体之前, 所有函数的签名都已经知晓。

#### PASS 3: 解析函数体

在第三个 PASS 中, 我们解析所有函数的函数体, 解析过程大致为: 自顶向下遍历 AST 中的每个节点, 解析过程中, 持续维护**类型上下文**和**符号上下文**, 并进行类型检查和符号链接。解析的结果是一个带有语义信息的 AST, 其中每个符号引用都链接到符号表中实际的定义, 每个表达式节点都带有类型信息。
