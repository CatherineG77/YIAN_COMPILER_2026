# LLVM 入门手册

## 1. LLVM 是什么

LLVM 可以理解为一种“中间表示”体系。源语言先被翻译成 LLVM IR，再由后端工具继续优化、生成机器码。

你可以把 LLVM IR 看成一种带类型的汇编语言。它比汇编更高级一些，有：

- 明确的类型系统
- 基本块和跳转
- SSA 形式的临时变量
- 指针运算和内存读写

## 2. LLVM IR 核心对象

### 2.1 值

对应 `llvm.an` 里的 `LLValue` 类型

LLVM IR 里的值分两类:

- 常量：例如 `0`、`1`、`42`
- 虚拟寄存器变量：例如 `%_0`、`%_1`、`%_2`

LLVM IR 中所有值都必须具有一个明确的类型，例如 `i32`、`i8*`、`{ i8*, i64 }` 等。LLVM IR 是强类型语言，在进行运算时，LLVM 会检查类型是否严格匹配。

LLVM IR 中的变量遵循**静态单赋值（SSA, Static Single Assignment）**形式，SSA 要求:

- 每个变量只能被赋值一次
- 每个变量必须在使用前定义

之所以将变量称为“虚拟寄存器”，是因为它们并不直接对应物理寄存器，在程序中你可以申请任意数量的变量，变量的大小不必要和物理寄存器大小一致。LLVM 后端会负责将这些虚拟寄存器映射到实际的物理寄存器或内存地址。

### 2.2 类型

对应 `llvm.an` 里的 `LLType` 类型

LLVM IR 支持的类型包括:

- 整数类型：`i1`、`i8`、`i16`、`i32`、`i64`(不区分符号)
- 浮点类型：`float`（32 位）、`double`（64 位）
- 指针类型：`T*` 表示指向类型 `T` 的指针
- 数组类型：`[N x T]` 表示包含 `N` 个类型 `T` 元素的数组
- 聚合类型：`{ T1, T2, ... }` 表示包含多个字段的结构体类型, 字段类型分别是 `T1`、`T2` 等

### 2.3 基本块和控制流

对应 `llvm.an` 里的 `LLBasicBlock` 类型

基本块是 LLVM IR 中的一个重要概念，它表示一段连续执行的指令序列。每个函数由若干个基本块组成，基本快包含以下要素:

- 每个函数必须有一个入口基本块，通常命名为 `.entry`
- 基本块标签：以冒号结尾的标识符，例如 `.entry:`, 用于跳转指令的目标
- 指令序列：基本块内的 LLVM IR 指令，按照顺序执行
- 非终结指令：如算术运算、内存访问、函数调用等, 指令序列中, 除了最后一条指令外, 其他指令都**必须**是非终结指令
- 终结指令：如 `br`（无条件跳转）、`cond_br`（条件跳转）、`ret`（返回）、`unreachable`（不可达指令）等, 终结指令**必须**是基本块中的最后一条指令

因此:

- 基本块内的指令一定是顺序执行的
- 一个函数的基本块之间通过跳转指令连接，形成一个**有向图**，这个图成为函数的**控制流图（CFG, Control Flow Graph）**

### 2.4 函数

对应 `llvm.an` 里的 `LLFunction` 类型

不同于汇编语言，LLVM IR 中有明确的函数定义和调用机制。函数定义以 `define` 开头，指定返回类型、函数名和参数列表。函数调用使用 `call` 指令，指定被调用函数和实参。

### 2.5 模块

对应 `llvm.an` 里的 `LLModule` 类型

模块是 LLVM IR 的最外层结构，包含:

- 类型声明, 例如: 结构体类型的定义等
- 外部函数声明, 例如: `malloc`、`free` 等库函数的声明
- 全局变量和字符串, 例如: 用于存储常量字符串的全局变量
- 函数定义, 例如: `main` 函数和其他函数的定义
- 其他架构信息

本次实验中，一个源代码文件编译的终产物就是一个 LLVM 模块

## 3. LLVM IR 指令

类似于汇编语言中有各种指令，LLVM IR 也有丰富的指令集。本次实验需要了解的指令如下:

### 3.1 跳转指令

跳转指令都是终结指令

#### 3.1.1 无条件跳转 `br`

形式：

```llvm
br label %target
```

表示直接跳到目标基本块。

### 3.1.2 条件跳转 `cond_br`

形式：

```llvm
br i1 %cond, label %then, label %else
```

表示如果条件为真就跳到 `then`，否则跳到 `else`。

### 3.1.3 返回 `ret`

形式：

```llvm
ret i32 %_3
ret void
```

分别表示返回一个值和无返回值。

### 3.1.4 `unreachable`

形式：

```llvm
unreachable
```

表示这里不应该执行到。如果真的走到这里，说明程序有逻辑错误。

### 3.1.5 `switch`

形式大致是：

```llvm
switch i32 %x, label %default [
	i32 0, label %case0
	i32 1, label %case1
]
```

它用于多分支跳转，根据 `%x` 的值跳到不同的基本块。如果 `%x` 不匹配任何 case，就跳到 `default`。它类似于 C 语言中的 `switch` 语句, 但是有以下不同点:

- 穷尽性: LLVM 的 `switch` 要求所有可能的值都必须被覆盖，也就是必须有一个 `default` 分支来处理未匹配的情况
- 无 fall-through: LLVM 的 `switch` 不支持 case 之间的 fall-through，每个 case 都必须明确指定跳转目标

## 3.2 phi 指令

这是一个专门为 SSA 形式设计的指令，用于在控制流合并点选择正确的值。设想下面的情况:

```cpp
bool cond = foo() && bar();  // 假定 foo() 和 bar() 都返回 bool 类型
```

翻译成 LLVM IR 大致如下:

```llvm
%foo_result = call i1 @foo() ; 调用 foo()，得到结果
br i1 %foo_result, label %then, label %end ; 根据 foo() 结果跳转

.then:
%cond = call i1 @bar() ; 如果 foo() 是 true，逻辑运算的结果取决于 bar() 的结果
br label %end

.end:
%cond = i1 0  ; 如果 foo() 是 false，逻辑运算的结果直接是 false, 不需要调用 bar()
; 后续逻辑
```

上述代码中，`%cond` 在两个基本块中被赋值了两次，这违反了 SSA 形式的规则。为了满足 SSA 形式，我们需要引入 `phi` 指令来合并这两个赋值:

```llvm
%foo_result = call i1 @foo() ; 调用 foo()，得到结果
br i1 %foo_result, label %then, label %end ; 根据 foo() 结果跳转

.then:
%bar_result = call i1 @bar() ; 如果 foo() 是 true，逻辑运算的结果取决于 bar() 的结果
br label %end

.end:
%cond = phi i1 [ 0, %entry ], [ %bar_result, %then ] ; 使用 phi 指令合并结果
; 后续逻辑
```

上面的 `phi` 指令表示:

- 如果控制流来自 `entry` 基本块, 那么 `%cond` 的值是 `0`（即 false）
- 如果控制流来自 `then` 基本块, 那么 `%cond` 的值是 `%bar_result`（即 `bar()` 的结果）

因此:

- `phi` 指令允许我们在控制流合并点根据不同的路径选择正确的值
- `phi` 指令必须覆盖当前基本块在 CFG 中所有可能的前驱基本块

## 3.3 call 指令

用于函数调用, 形式例如:

```llvm
%_0 = call i32 @foo(i32 1, i32 2) ; 调用有返回值的函数, 返回值存储在 %_0 中
call void @bar(i8* %p) ; 调用无返回值的函数
```

## 3.4 聚合类型相关指令

### 3.4.1 `insertvalue`

用于将一个值插入到聚合类型（如结构体）中, 形式例如:

```llvm
%_0 = insertvalue %struct.MyStruct undef, i32 3, 0
%_1 = insertvalue %struct.MyStruct %_0, i1 1, 1
```

对第一条指令的解释:

- `undef` 表示一个未定义的结构体值, 作为构造的起点
- `i32 3` 是要插入的值
- `0` 是要插入的字段索引, 表示将 `3` 插入到结构体的第 0 个字段
- 指令总体的意思是创建一个新的结构体值, 其第 0 个字段被设置为 `3`, 其他字段保持未定义, 返回的新值存储在 `%_0` 中

对第二条指令的解释:

- `%_0` 是前一条指令生成的结构体值, 作为当前插入的基础
- `i1 1` 是要插入的值
- `1` 是要插入的字段索引, 表示将 `1`插入到结构体的第 1 个字段
- 指令总体的意思是基于 `%_0` 的结构体值, 创建一个新的结构体值, 其第 1 个字段被设置为 `1`, 其他字段保持与 `%_0` 相同, 返回的新值存储在 `%_1` 中

字段的索引必须是常量整数, 此指令也可以用于将一个值插入到数组类型中, 但在本实验中我们主要用它来构造结构体值。

### 3.4.2 `extractvalue`

用于从聚合类型中提取一个字段的值, 形式例如:

```llvm
%_2 = extractvalue %struct.MyStruct %s, 1
```

这条指令的意思是从结构体值 `%s` 中提取第 1 个字段的值, 返回的值存储在 `%_2` 中。

字段的索引必须是常量整数, 该指令也可以用于从数组类型中提取元素值, 但在本实验中我们主要用它来读取结构体字段。

### 3.4.3 `getelementptr`

给定某个聚合类型的指针, 计算其中某个字段的地址, 形式例如:

```llvm
%_3 = getelementptr %struct.MyStruct, %struct.MyStruct* %p, i64 0, i32 1
%_4 = getelementptr i32, i32* %ptr, i64 3
%_5 = getelementptr [4 x i32], [4 x i32]* %arr, i64 0, i32 2
```

上面 3 个例子分别对应三种常见的用法:

1. 给定一个结构体指针 `%p`, 计算其中第 1 个字段的地址, 返回的地址存储在 `%_3` 中
2. 给定一个指针 `%ptr`, 将其往后移动 3 个 `i32` 的位置, 返回的新地址存储在 `%_4` 中
3. 给定一个数组指针 `%arr`, 计算其中第 2 个元素的地址, 返回的地址存储在 `%_5` 中

三种用法分别被封装成了 `builder.field_ptr`、`builder.offset` 和 `builder.index` 这三个方法, 但它们底层都是通过 `getelementptr` 指令来实现的。

`getelementptr` 指令的一般化形式是:

```llvm
%result = getelementptr <type>, <type>* <ptr>, <index1>, <index2>, ...
```

其中:

- `<type>` 是指针指向的类型
- `<ptr>` 是要进行地址计算的指针
- `<index1>`, `<index2>`, ... 是一系列索引, 用于指定要访问的字段或元素位置

至于 `getelementptr` 为何要支持多重索引, 以及它的具体语义, 本次实验不做要求, 感兴趣的同学可以自行查阅 LLVM 官方文档。

## 3.5 内存访问相关指令

### 3.5.1 `bitcast`

用于在不同类型的指针之间进行转换, 形式例如:

```llvm
%_6 = bitcast i8* %raw_ptr to i32*
```

这条指令的意思是将一个 `i8*` 类型的指针 `%raw_ptr` 转换为 `i32*` 类型的指针, 返回的新指针存储在 `%_6` 中。

显然, 这种转换并不改变指针的数值, 只是改变了它的类型信息, 因此它不会进行任何实际的地址计算或内存访问, 只是告诉 LLVM 后端在使用 `%_6` 时按照 `i32*` 的方式来解释这个地址。

通常用于动态内存分配的场景, 例如我们通过 `malloc` 得到一个 `i8*` 类型的原始指针, 然后使用 `bitcast` 将其转换为目标类型的指针, 以便后续的内存访问指令能够正确地操作这个地址。

### 3.5.2 `malloc` 与 `free`

实际上，LLVM IR 本身并没有内置的 `malloc` 和 `free` 指令，这些函数通常是通过外部函数声明来使用的，例如:

```llvm
declare i8* @malloc(i64)
declare void @free(i8*)
```

`LLBuilder` 提供的 `malloc` 与 `free` 方法实际上是调用了上述外部函数来实现动态内存分配和释放的功能。

### 3.5.3 `alloca`

`alloca` 指令用于在函数的栈帧上分配内存, 形式例如:

```llvm
%_7 = alloca i32
```

这条指令的意思是在当前函数的栈帧上分配一个 `i32` 类型的内存空间, 返回的指针存储在 `%_7` 中。

这条指令用于为函数的局部变量分配内存, 按照本次实验设计, 所有局部变量都会在函数入口处统一使用 `alloca` 分配内存, 即使这个变量嵌套在深层作用域中, 并非在函数入口处声明

### 3.5.4 `load` 与 `store`

`load` 指令用于从内存地址读取值, 形式例如:

```llvm
%_8 = load i32, i32* %_7
```

这条指令的意思是从指针 `%_7` 指向的内存地址读取一个 `i32` 类型的值, 返回的值存储在 `%_8` 中。

`store` 指令用于将一个值写入内存地址, 形式例如:

```llvm
store i32 42, i32* %_7
```

这条指令的意思是将 `i32` 类型的值 `42` 写入指针 `%_7` 指向的内存地址。

### 3.5.5 `ptrtoint`

`ptrtoint` 指令用于将一个指针类型的值转换为整数类型, 形式例如:

```llvm
%_9 = ptrtoint i32* %_7 to i64
```

这条指令的意思是将一个 `i32*` 类型的指针 `%_7` 转换为 `i64` 类型的整数, 返回的整数存储在 `%_9` 中。

这条指令与 `bitcast` 类似, 都是对一个指针的值重新解释, 用于某些需要将指针作为整数处理的场景, 例如计算指针之间的距离等

## 3.6 运算指令

### 3.6.1 比较运算

本次实验涉及到的比较指令大致分为两大类: 用于整数的 `icmp` 和用于浮点数的 `fcmp`。它们的形式分别是:

```llvm
%reg = icmp eq|ne|slt|ult|sgt|ugt|sle|ule|sge|uge <type> <op1>, <op2>
%reg = fcmp oeq|one|olt|ogt|ole|oge <type> <op1>, <op2>
```

其中:

- `icmp` 支持多种比较操作, 包括等于（`eq`）、不等于（`ne`）、有符号小于（`slt`）、无符号小于（`ult`）等, 之所以区分有符号和无符号比较, 是因为 LLVM IR 中的整数类型本身不区分符号, 因此需要通过不同的比较操作来表达有符号和无符号的语义
- `fcmp` 主要用于浮点数比较, 支持的操作包括等于（`oeq`）、不等于（`one`）、小于（`olt`）、大于（`ogt`）等, 其中 `o` 前缀表示这是一个有序比较, 也就是说如果任一操作数是 NaN, 比较结果将是 false(根据 IEEE 754 标准, 浮点数的值域包括 NaN, NaN 与任何值的比较结果都是 false)
  - 实际上, `fcmp` 还支持无序比较（`ueq`、`une`、`ult`、`ugt` 等）, 感兴趣的同学可以自行探索它们的语义和使用场景

### 3.6.2 算术运算

本次实验涉及到的算术指令主要是 `add`、`sub`、`mul`、`div` 等, 它们的形式:

```llvm
%reg = add|fadd <type> <op1>, <op2>
%reg = sub|fsub <type> <op1>, <op2>
%reg = mul|fmul <type> <op1>, <op2>
%reg = sdiv|udiv|fdiv <type> <op1>, <op2>
%reg = srem|urem|frem <type> <op1>, <op2>
```

注意:

- `add`、`sub`、`mul` 提供了整数版本与浮点版本
- `div` 和 `rem` 的整数版本区分了有符号（`sdiv`、`srem`）和无符号（`udiv`、`urem`）两种情况, 这是因为 LLVM IR 中的整数类型本身不区分符号, 因此需要通过不同的指令来表达有符号和无符号的除法和取模语义
- 不存在专门的一元负指令, 可以通过 `sub` 指令将 `0` 与一个值进行相减来实现一元负的效果

### 3.6.3 位运算

本次实验涉及到的位运算指令主要是 `and`、`or`、`xor`、`shl`（左移）、`lshr`（逻辑右移）和 `ashr`（算术右移）, 它们的形式:

```llvm
%reg = and <type> <op1>, <op2>
%reg = or <type> <op1>, <op2>
%reg = xor <type> <op1>, <op2>
%reg = shl <type> <op1>, <op2>
%reg = lshr|ashr <type> <op1>, <op2>
```

注意:

- 位运算指令只适用于整数类型, 不支持浮点数
- 位运算指令不区分有符号和无符号
- 左移指令只有一种, 右移指令区分了逻辑右移（`lshr`）和算术右移（`ashr`）, 根据被移位的值的符号位是否需要保持不变来选择使用哪种右移指令
- 不存在专门的按位取反指令, 可以通过 `xor` 指令将一个值与 -1 进行异或来实现按位取反的效果
